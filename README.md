# Google Search Engine — Haskell & Python

## Project Overview

This project implements a simple Google-like search engine using both **imperative** and **functional** programming approaches.

The project contains implementations in both **Python** and **Haskell**, including different search algorithms, sorting, duplicate removal, search-table creation, and table validation.

---

# Project Structure and Setup

The project contains both Python and Haskell implementations.

### Python

The Python implementation contains:

* `Google.py` — main program for the search engine and performance measurement.
* `ordsearch.py` — contains the linear and binary search functionality.
* `diamond.py` — contains the sorting functionality.

To run the Python implementation, create a folder named `resources` in the **same directory as `Google.py`** and place the text files you want to search inside it.

Example:

```text
project/
├── Google.py
├── ordsearch.py
├── diamond.py
└── resources/
    └── your-text-files.txt
```

Run the Python version with:

```bash
python Google.py
```

### Haskell

For the Haskell implementation, place the text files you want to search in the **same directory as `Google.hs`**.

Example:

```text
project/
├── Google.hs
├── your-text-files.txt
└── ...
```

Run the Haskell version by providing the text files as arguments:

```bash
runghc Google.hs 'your-text-file-1.txt' 'your-text-file-2.txt'
```

The text files are **not included in this repository**. Users need to provide their own text files when running the programs.

# Python Implementation

### Search

We implemented two different search methods in `ordsearch.py`:

* **Linear search**
* **Binary search**

### Sorting

We implemented a **merge sort** function in `diamond.py`.

### Duplicate Removal

We implemented `mergeDict`, which uses a **dictionary/hash table** to find and remove duplicate entries.

After creating the dictionary, we convert the dictionary back into a list and return the result.

### Performance Measurement

In `Google.py`, we added timing measurements to check how long different parts of the program take.

The program measures:

* Time spent reading the text files
* Time spent creating the search table
* Time spent searching the table

# Haskell Implementation

For the functional implementation, we reused the `mergeSort` and `dedup` functions from previous work.

### `getKeys`

`getKeys` takes a collection of pairs and returns all the keys (words) as a list of strings.

We use:

1. `map` to extract the keys.
2. `mergeSort` to sort the keys.
3. `dedup` to remove duplicate keys.

```haskell
getKeys :: Pairs -> [String]
```

### `getItems`

`getItems` takes a key and a collection of pairs and returns all filenames associated with that key.

The filenames are sorted and duplicate filenames are removed.

```haskell
getItems :: Pairs -> String -> [FilePath]
```

### `mergeBackPairs`

`mergeBackPairs` combines the list of keys and the corresponding lists of filenames into a `Table`.

For example:

```text
["cat", "dog"]
[["brian.txt"], ["grail.txt", "eyre.txt"]]
```

becomes:

```text
[
    ("cat", ["brian.txt"]),
    ("dog", ["grail.txt", "eyre.txt"])
]
```

### `makeTable`

`makeTable` creates the complete search table.

It:

1. Gets all unique, sorted keys using `getKeys`.
2. Gets the filenames for each key using `getItems`.
3. Combines the keys and filenames using `mergeBackPairs`.

### Table Validation

We also implemented functions to validate the generated table.

The validation checks:

* There are no duplicate keys.
* There are no duplicate filenames for the same key.
* There are no empty filename lists.

The final validation function is:

```haskell
isValidTable :: Table -> Bool
```

# QuickCheck

We also created a QuickCheck property to verify that tables generated by `makeTable` are valid.

Start GHCi with:

```bash
ghci Google.hs
```

Then run:

```haskell
quickCheck prop_makeTableValid
```

Example result:

```text
+++ OK, passed 100 tests.
```

This checks the validity of tables generated from randomly generated `Pairs`.
